regulatory-return-automation

SQL · Python · Excel output · 14 tests

A monthly regulatory return built by a pipeline that refuses to produce the file when the numbers can't be trusted. Ten blocking controls and one review warning run before anything is written. The headline total is recomputed by a second route that shares no code with the first.

  • Blocked runs write no file and still leave an audit record of what was stopped and why.
  • A line that moved a lot since last month doesn't block the return. It's flagged inside the workbook, where whoever files it will see it.
  • Money stays in integers end to end, so totals reconcile exactly.

aliased-sql-assistant

Context engineering · SQL guardrails · eval harness · 40 tests

A text-to-SQL assistant that never sees a real table name, a real column name or a row of data. The context file is written by hand and tested like code, so it can't quietly fall behind the schema.

  • Of 18 candidate answers, 8 are stopped by guardrails and 4 pass every guardrail and are still wrong. Those four are the reason golden answers exist.
  • One query returns the right answer and is blocked anyway, because it would scan the whole table.
  • No network calls and no API keys. It works with any model.

Getting AI into a regulated environment turns out to be an architecture problem, not a prompting one.

metrics-source-of-truth

Metric contracts · gold tables · daily alert · 16 tests

One written definition per metric, gold tables built from those definitions, and a daily alert that reads the same tables everyone else does. The same "monthly active users" question gives six defensible answers on this data. The dangerous ones are the answers that are only 1.8% apart.

  • The documentation is generated from the same registry the tables are built from, and a test fails if they drift.
  • The first version of the alert flagged 77 days in ten months. The third flags 8 in a year, and the README explains what changed.

year-in-review-etl

SQL window functions · validation · 16 tests

Turns a year of transactions into one personalised summary per customer, and decides what to do about the customers a summary doesn't fit: the ones who joined three weeks ago, made one payment, or did nothing at all.

  • Four card variants, and one rule behind them: never show a number that would embarrass us.
  • Every metric is computed twice, by two implementations that share nothing, and the two have to agree.
  • If validation fails, no cards are written.

Python build · plain HTML, CSS and JavaScript · 14 tests

An interactive leadership dashboard that's one 88 KB HTML file. No login, no server, no install. It holds aggregates only, folds small cells before the data is written, and the build fails if the file references anything external.
